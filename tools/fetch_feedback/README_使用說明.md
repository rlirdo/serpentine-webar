# 撈取 GitHub 問卷與遊戲前後測資料（v7.0.0，2026/11/25；v6.0.0 為 2026/11/11；v5.0.0 為 2026/11/05；v4.0.0 為 2026/11/04；v3.0.0／v2.0.0 為 2026/10/29、初版 v1.0.0 為 2026/10/22）

## 用途
把 WebAR 遊戲回饋問卷（第 36 屆環境教育研討會壁報 A155-07）的回覆，從 GitHub repo
`rlirdo/serpentine-webar` 的 `feedback/responses/` 資料夾下載到本機，並自動彙整成 CSV 與 Excel。
每次只下載本機還沒有的新檔，可以重複按、不會重複下載。
v3.0.0 起另可下載 **WebAR 遊戲前後測**（`feedback/game/`）並匯出 Excel（見下方 v3.0.0 一節）。
v7.0.0 起另可下載 **研究用前後測**（`feedback/test/`，遊戲班＋對照班）並匯出 Excel 與分析用 CSV（見下方 v7.0.0 一節）。

- 程式檔名：`撈取GitHub問卷與遊戲前後測資料.exe`（v7.0.0）。v6.0.0、v5.0.0、v4.0.0 的 exe、原始碼、測試與說明另存於 `舊版\`（檔名加 `_v6.0.0`／`_v5.0.0`／`_v4.0.0`）。v3.0.0 的 exe 移到 `舊版\撈取GitHub問卷與遊戲前後測資料_v3.0.0.exe`
  （原始碼另存 `舊版\fetch_feedback_v3.0.0.py`）。原本的 `撈取GitHub問卷資料.exe`（v2.0.0）保留不動，
  另存一份於 `舊版\撈取GitHub問卷資料_v2.0.0.exe`；三者共用同資料夾的 `config.json`。原回饋問卷功能與輸出完全不變。

## v7.0.0 新增：研究用前後測（遊戲班／對照班，feedback/test）（2026/11/25）
準實驗研究：每個學段一個**遊戲班**、一個**對照班**，兩班都在課前、課後作答**同一份整份 10 題**（墨玉題庫：國小 E1–E10、國中 J1–J10），
後測後選一項行動承諾。遊戲 repo 的上傳 schema 為 **`webar-test-v1`**，中繼寫入 `feedback/test/`（不是 `feedback/game/`）：

| 組別 | 來源 | `group` | `mode` |
|---|---|---|---|
| 遊戲班 | 遊戲研究模式 `play.html?study=1&grade=…&event=…`（`ar.html` 同） | `game` | `play`／`ar`；後測另帶八關星數 `stars`、`totalStars`、`restarts`（闖關途中重新整理後從第 1 關重闖的次數） |
| 對照班 | 測驗頁 `test/?grade=…&event=…` | `control` | `test`（不帶星數） |

> **資料何時開始有**：中繼 Code.gs v5 需由您重新部署（新版本）後才會寫入 `feedback/test/`。GitHub 上還沒有這個資料夾時，
> 本工具顯示「**尚無研究資料**」並輸出空白格式的 Excel，不會報錯。原有回饋問卷與遊戲前後測功能、輸出格式完全不變。

### 操作（視窗下方切到「研究用前後測（遊戲班／對照班）」分頁）
原「WebAR 遊戲前後測」區塊原封不動移到第一個分頁。研究用分頁：
1. **起／迄**（依上傳時間，格式同遊戲區塊；「今天」「全部清空」）。
2. **活動**：下拉有 `CTRL-TEST`（對照班預設）、`STUDY-GAME`（遊戲班預設），也可直接輸入班級代碼（不分大小寫）；「全部」＝不篩選。
3. **組別**（全部／遊戲班／對照班）、**版本**（全部／國小／國中）。
4. 按「**下載並匯出研究用 Excel…**」→ 選存檔位置（預設檔名 `研究用前後測_<起>至<迄>_匯出<時間>.xlsx`，沒設區間時為 `研究用前後測_全部_匯出<時間>.xlsx`）。
   程式只下載本機沒有的新檔到 `<目的資料夾>\test_json\`，同時在 xlsx 旁另存兩個分析用 CSV：`<檔名>_分析用_elem.csv`、`<檔名>_分析用_junior.csv`（UTF-8 含 BOM）。
   分頁內顯示「研究資料本機 N 筆」。

### 彙整規則
- **配對**：以 `sid`（一次作答的代碼，前後測相同）把前測與後測配成一列（一位學生一列）。
- **重複上傳**：同一 `sid`＋同一階段有多筆時，留 `submitted_at` 最早的一筆，其餘列在「已略過（重複）」（含保留的檔名）。
- **只有前測**：保留，標示「否（未完成後測）」，後測與進步分數留空。
- **缺獨立前測檔**：後測紀錄本身帶完整前測作答；該 sid 沒有前測檔時改用它，「前測作答來源」寫「後測檔內的前測作答」並在註記說明（前測時間留空）。
  兩者都有但內容不同時以前測檔為準並註記。
- **計分**：只算 8 題計分題；態度題（國小 E3、E7；國中 J3、J8）不計對錯（JSON 送什麼都不採用），只記選了哪個選項。
  對錯一律依本工具題庫重算（正解＝原始選項索引 0）。
- 先依起迄時間、活動、組別、版本篩選，再去重、配對。

### Excel 工作表
| 工作表 | 內容 |
|---|---|
| 學生彙整 | 一列一位：序號、活動代碼、組別（遊戲班／對照班）、版本、pid、sid、前測時間、後測時間、作答模式；前測 Q1–Q10（題號、選項索引、選項文字、對錯 1/0，態度題寫「—」）、後測 Q1–Q10 同上；前測總分(8題)、後測總分(8題)、進步分數；態度題 1／2 的前後測選擇（文字）；行動承諾；第 1–8 關星數、總星數、restarts（遊戲班）；裝置摘要（例：Android／Chrome）；完成後測；前測作答來源；資料來源註記；前測／後測檔名；UA |
| 分析用_國小elem、分析用_國中junior | 給 jamovi 用的數值表（英文欄名）：`row sid pid event group group_code(遊戲班1/對照班0) grade mode completed(1/0) pre_from_post(1/0) pre_total post_total gain`、8 題計分題 `pre_E1…`／`post_E1…`（1/0；國中為 `J*`）、`att1_pre att2_pre att1_post att2_post`（態度題原始選項索引 0–3）、`commit`（承諾索引 0–3）、`stars1–stars8 total_stars restarts`（對照班空白）。缺值一律空白。 |
| 統計 | 篩選條件與筆數；依「組別｜版本｜活動代碼」：學生數、前測人數、完成前後測人數、前測平均、完成者前測平均、後測平均、平均進步、平均總星數；每組的逐題前後測答對率（後測只算完成者）、態度題各選項前後測人數、行動承諾分布 |
| 已略過（重複） | 檔名、上傳時間、sid、pid、階段、組別、版本、活動代碼、保留的檔名、原因 |
| 題目對照 | 20 題：題號、版本、面向、是否計分（態度題寫「否」）、題目、選項 A–D（原始順序）、正解、正解索引、解說 |

**為什麼國小、國中分兩張分析表**：兩版題號與題目不同（E1 與 J1 不是同一題），若放同一張表，同一欄會混到不同題目，
或要留大量空白欄，丟進 jamovi 時容易誤把不同題目一起分析。分開後每張表的題目欄都對應同一題；總分、進步分數、
組別代碼的欄名兩張相同，需要跨版本比較總分時，可把兩張表上下合併（逐題欄位請勿合併）。

### 不互動模式
```
撈取GitHub問卷與遊戲前後測資料.exe --research-export <資料夾> <輸出.xlsx> [--from "YYYY-MM-DD HH:MM"] [--to "YYYY-MM-DD HH:MM"] [--event 活動代碼] [--group 遊戲班|對照班] [--grade 國小|國中] [--offline]
```
`--group` 也接受 `game`／`control`，`--grade` 也接受 `elem`／`junior`。`--offline` 不連網，只用 `<資料夾>\test_json\`。
摘要寫入 `<資料夾>\研究用前後測_匯出結果.txt` 後結束（成功結束碼 0）。

### 題庫同步
研究用題庫就是墨玉題庫（`QUESTION_BANK`）；行動承諾四選一為 `COMMITS`。測試 `test_research_bank_matches_game_repo` 逐題比對遊戲
`js/content.js`（題目、四選項順序、正解 0、面向、行動承諾文字），並檢查 `js/study.js`（`N = 10`、`ATTITUDE = "態度"`）與中繼
`feedback/relay/Code.gs`（`TEST_ATTITUDE`、`TEST_N`、`TEST_DIR`）一致。遊戲改題目時須同步修改並重跑測試。

## v3.0.0 新增：WebAR 遊戲前後測下載與 Excel 匯出（2026/10/29）
壁報右上方「掃描即玩」的 WebAR 墨玉晶格修復任務遊戲，玩家做完**前測**與整局結束（**後測**）時，
遊戲會各上傳一筆紀錄到 GitHub repo `rlirdo/serpentine-webar` 的 `feedback/game/` 資料夾。
本工具可把這些紀錄下載到本機、依日期時間篩選、排除重複作答後，匯出成 Excel 存到您指定的路徑。

> **資料何時開始有**：遊戲端與 Apps Script 中繼需由您**重新部署 Apps Script** 後才會開始寫入 `feedback/game/`；
> 詳細步驟見遊戲 repo（`serpentine-webar`）的說明。部署前按匯出會顯示 GitHub 上 0 筆，屬正常。

### 操作（視窗下方「WebAR 遊戲前後測（feedback/game）」區塊）
1. **起／迄**：格式 `YYYY-MM-DD HH:MM`（台北時間），例如 `2026-10-31 09:00`～`2026-11-01 17:30`。
   - 留空＝不限；「迄」含該分鐘（填 17:30 會含 17:30:59 以前）；只填日期時「迄」＝當天 23:59:59。
   - 「今天」按鈕自動填入今天 00:00～23:59；「全部清空」＝撈全部。
2. **重複判定**：1–720 分鐘，預設 30（會記在 `config.json` 的 `game_window`；token 一律不存）。
3. 按「**下載並匯出 Excel…**」→ 選存檔位置（預設目的資料夾、檔名 `遊戲前後測_YYYYMMDD-HHMM.xlsx`）。
   程式只下載本機沒有的新檔到 `<目的資料夾>\game_json\`，再篩選、去重、配對、統計，日誌框顯示摘要，完成後詢問是否開啟 Excel。
4. 上方狀態列顯示「遊戲紀錄本機 N 筆」。

### 去重規則（避免同一位玩家短時間內重複作答）
- 玩家以 **`pid`（匿名玩家代碼）** 辨識：存在玩家手機瀏覽器，同一支手機每次玩都相同（無痕模式除外）。
- 依「同一 pid＋同一階段（前測／後測）」分組、按上傳時間排序：**第一筆保留**；之後每筆若與「最近一筆被保留的紀錄」相差**未滿 30 分鐘** →
  判為重複、略過（列在「已略過(重複)」工作表，含與基準筆差幾分鐘）；**超過 30 分鐘**視為再玩一次而保留，並成為新的比較基準。
  也就是 30 分鐘內只取其**第一次前測、第一次後測**。
- 缺 pid 或上傳時間無法解析的紀錄無法判定，一律保留並在「備註」註明。
- 先依起迄時間篩選，再做去重。

### 前後測配對
- 以 **`sid`（本次遊玩代碼，每次重新載入頁面新產生）** 把同一次遊玩的前測與後測配成一列。
- 只有前測沒有後測＝玩到一半，後測欄留空；只有後測（前測上傳失敗）也列出，前測答案取自後測紀錄內的 `pre`。

### Excel 工作表
| 工作表 | 內容 |
|---|---|
| 玩家彙整 | 一列一次遊玩：序號、pid、sid、版本（國小／國中）、模式（AR／免相機）、前測／後測時間、前測 Q1–Q3（題號、選項文字、答對 1/0）、前測答對數、後測 Q1–Q5、後測同 3 題答對數、後測答對數、進步（後測同 3 題−前測）、八關星數、總星數、四面向 %、小行動承諾、備註、檔名、UA |
| 前測 | 保留的前測紀錄逐筆（含選項索引與選項文字） |
| 後測 | 保留的後測紀錄逐筆（Q1–Q5＋星數、面向、承諾） |
| 已略過(重複) | 被判重複的紀錄：檔名、時間、pid、階段、基準筆檔名、相差分鐘、原因 |
| 統計 | 篩選區間、重複判定分鐘、本機總筆數、區間內筆數、保留／略過筆數、玩家數、完整遊玩數、國小／國中人數、AR／免相機人數、前測平均、後測同 3 題平均、平均進步、後測 5 題平均、四面向平均 %、E1–E10／J1–J10 每題前測／後測作答數與答對率 |

所有文字欄位都有公式注入防護（以 `=`、`+`、`-`、`@` 開頭者加 `'`）。字型微軟正黑體、表頭深藍底白字。

### JSON 欄位（schema `webar-game-v1`，檔名 `YYYYMMDD-HHMMSS_<pre|post>_<6碼>.json`，台北時間）
| 欄位 | 說明 |
|---|---|
| `submitted_at` | 上傳時間（ISO 8601，+08:00）；篩選與去重依此欄 |
| `event` | 活動代碼（SEET2026-A155-07） |
| `pid` / `sid` | 匿名玩家代碼（12 碼）／本次遊玩代碼 |
| `phase` | `pre` 前測（做完即上傳）／`post` 後測（整局結束上傳） |
| `grade` / `mode` | `elem` 國小版、`junior` 國中版／`ar` 手機掃任務卡、`play` 免相機 |
| `pre` / `post` | 題目陣列 `{id, facet, pick, correct}`；`pick`＝原始選項索引 0–3（正解一律 0）；前測 3 題、後測 5 題（同 3 題＋行動面向 1 題＋其他面向 1 題） |
| `preScore` `postSame3` `postScore` | 前測答對數、後測同 3 題答對數、後測答對數（本工具以題目陣列重算，缺漏時才採用此欄） |
| `stars` / `totalStars` | 八關星數（0–3）／總星數（0–24） |
| `facets` | 四面向 %（知識、態度、行動、探究，0–100） |
| `commit` / `ua` | 小行動承諾／瀏覽器 UA |

欄位缺漏或型別不對時視為空白，不會讓程式中止；JSON 無法解析者另存 `game_json\壞檔\`。
題庫（`QUESTION_BANK`）是從遊戲 repo `js/content.js` 的 `BANK` 原樣複製；**遊戲改題目時須同步修改 `fetch_feedback.py`**，跑測試後重新打包。

## GitHub Token（通常不用填）
